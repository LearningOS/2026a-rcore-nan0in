## 简答题

### stride 为什么需要处理回绕？

1. **8 位例子。** `p2` 从 250 加 10 得到真实累计值 260，按8位变量与后变为 4。用普通无符号比较时，4 小于 255，调度器会错误地再次选 `p2`；按真实累计值则应选 `p1`。
2. **差距上界。** 假设同一批任务初始 stride 相同，且每轮只增加当前最小值。优先级至少为 2，所以每次增加量不超过 `floor(BigStride / 2)`。其他任务原本就在“旧最小值到旧最小值加上这一上界”的区间内，被选中的任务增加后也在该区间内。由此可归纳差距不会超过这个上界。中途任意加入或长期阻塞再进入的任务要另考虑其初值或重新入队策略。
3. **环绕比较。** 若实际差距始终严格小于整数范围的一半，令 `delta = self.0.wrapping_sub(other.0)`。差值为正且落在低半区时，`self` 的实际 stride **更大**；落在高半区时，差值等价于一个负数，`self` 的实际 stride **更小**。实现可将回绕差值解释为一个有符号数：

```rust
fn partial_cmp(&self, other: &Self) -> Option<core::cmp::Ordering> {
    Some((self.0.wrapping_sub(other.0) as i64).cmp(&0))
}
```

教材里`i8`是将stride理解为无限延伸的数轴即环形计数器：125 对 255 的差走为溢出255后再拿到的126而判为了`(125<255) == False`；129 对 255 正向，解释成有符号值为 −126，判为小。  
Rust 的 `BinaryHeap` 默认弹出最大项；若采用上述自然顺序，需要用反向排序的堆键。该比较依赖同时在队列中的值满足半区约束，不适用于任意环上数值集合。

我们实际用 `u128` 保存累计 stride，以留出运行余量。
