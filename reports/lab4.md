# lab4 文件系统与进程间通信

## 功能总结

本实验在 easy-fs 中实现了 `linkat`、`unlinkat` 和 `fstat`。硬链接通过新增目录项，让多个文件名指向同一个 inode；删除文件名只移除对应的目录项，最后一个链接和打开引用都消失后才回收 inode 与数据块。`fstat` 根据文件描述符返回 inode 编号、文件类型和当前链接数。

## 实现要点

- `linkat` 在根目录写入一个新的名字，指向旧名字的 inode 编号；两个名字读取的是同一份内容。
- `unlinkat` 只移除目录项。链接数统计的是还能找到该 inode 的名字，不是打开次数。若最后一个名字已经删除但 fd 仍打开，原 fd 仍可访问它；关闭最后一个打开引用后才回收 inode 和数据块。
- `fstat` 通过 fd 找到打开对象，从根目录统计同一 inode 的链接数，并把结果分段写回用户缓冲区，避免假设缓冲区所在的物理页连续。

## 简答题

### ch6 问答：根 inode 的作用

在本实验的平铺文件系统中，根 inode 是按名字查找文件的入口。它的目录数据由一组目录项组成，每项把一个文件名映射到相应的磁盘 inode 编号。打开文件时，内核先在根目录中找到编号，再定位磁盘 inode 及其数据块。

如果根 inode 的大小或数据块指针损坏，目录遍历可能漏掉条目、读错块，甚至触发文件系统错误；如果损坏的是某个目录项，则可能丢失该名字或把名字解析到错误的 inode。文件内容本身可能还在磁盘上，但正常的按名访问路径已失效。若再往损坏的目录写入，还可能扩大破坏。因此，排查时应区分目录损坏、文件 inode 损坏和内容块损坏。

### ch7 问答：管道与多进程通信

#### 1. 一个使用管道的实际例子

```sh
cat access.log | wc -l
```

Shell 创建管道，把 `cat` 的标准输出连到写端，把 `wc` 的标准输入连到读端。两个进程和 Shell 都应关闭不再使用的端点。这样，`wc` 可以边读边统计换行，不用创建中间文件；当所有写端关闭、缓冲区也读空后，读端才返回 EOF。如果 Shell 还持有一个写端，即使 `cat` 已经退出，`wc` 也可能继续等。

#### 2. 怎样减少多进程之间逐对建管道的开销？

可以设一个**消息中转进程**。每个参与者只与中转进程建立一个双向逻辑通道，例如用一读一写两条管道。发送方提交带目的进程标识与长度的消息，中转进程校验后将其放入接收方队列。这样，通道数随进程数线性增长，而不是为每对进程分别创建通道。

设计时应给每条消息规定最大长度、给每个接收队列设置容量，并明确接收方退出或队列满时的处理方式。例如，队列满就通知发送方稍后重试，避免一个慢进程堵住整个中转器。代价是多一次中转，以及中转进程形成单点瓶颈。
